# Phase 3 status - 2026-10-20

**State: in progress.** Solar Transit is the first playable Phase 3 slice. Phases 0-2 still have open device, content, and online reliability gates. This is a debug preview, not a feature beta or release build.

## Implemented slice

- TransitRun is a fixed-step, straight timed course using the browser course's two gap widths, 12-second limit, 10.6-unit base speed, jet and sail durations, speed multipliers, and cooldowns. The Unity route advances toward positive Z. The jet crosses the short amber gap; the sail crosses the longer cyan gap. A wrong or late ability causes a named crash, and standing still causes a timeout. The finish requires both gaps cleared.
- TransitGame provides the landing, Auto Drive on by default, touch Forward/JET/SAIL controls, Q/R and W/Up keyboard controls, pause/resume, retry, return to offline Arena, visible timer/checkpoints, active flight visuals, clear results, and a browser-local-equivalent best time in versioned non-sensitive PlayerPrefs.
- The existing offline Arena landing shows Solar Transit when the scene is packaged. The combined Android preview still contains offline Arena and the Phase 2 Online Room. The separate Phase 1 and Phase 2 build commands exclude this new scene.
- PhaseThreeBuild prepares the scene and creates desktop or Android development players without new packages, services, accounts, or server changes.

## All offline modes - 2026-10-22

At the user's request ("all game modes and complete game plays ... only offline; online later"), every browser solo mode now plays in the Android app.

**Rules port.** `Runtime/Sim/` is a plain C# port of `dist/simulation.js`, `arena-rules.js`, `maps.js`, `match.js`, `arena.js`, `operations.js`, and `grid-shift.js`: fixed 120 Hz steps, swept collisions, Hunter/Survivor/Trapper AI at Rookie/Standard/Expert, the 24-bullet mounted gun, ammo/nitro/rocket pickups, jet/sail flight, the three-minute shrink, decaying walls, operations, Grid Shift forms and discs, Duel/Arena match rules, and the Daily Signal seed (rules v3). It keeps the browser's operation order, seeded xorshift RNG, V8 `Math.hypot` algorithm, JS rounding and splice semantics, and stable-sort tie-breaking.

**Parity proof.** `scripts/sim-traces.mjs` records tick-by-tick traces from the browser modules (riders, trails, bullets, discs, pickups, RNG state, score, events, outcome; doubles compared as exact bit patterns), and `Editor/SimParity.cs` replays the same inputs through the C# port. `android-game/scripts/Verify-SimParity.ps1` runs both. Result: **29 scenarios, 197,949 ticks, 25 seed checks, 0 mismatches**, covering scripted Duel/Arena/Operations/Grid Shift/lesson play, long 4-AI and AI-driven-player rounds (up to 34,399 ticks), the late-round shrink, decaying walls, rockets, wall cuts, pickups, AI flight, and the Daily and round seeds. The ported AI and rules behave exactly as the browser's on desktop Mono; IL2CPP on ARM64 may fuse floating-point operations, so device results are not claimed bit-identical (no cross-play depends on it).

**Game.** The main menu's NEW GAME opens a mode select with Duel (rival, difficulty, map), Arena (difficulty, map, persistent or fading walls; three heats, survive two), Daily Signal (UTC seed, map, rival, Standard; daily best), Grid Shift (briefing; cycle and on-foot forms, disc, Echo AI), Operations (Portal Run, System Sweep, Arena Collapse, or the Journey with an optional Sentinel), Solar Transit (its existing course), and Play lesson. Each round has the 3-2-1 arrival countdown, chase camera (north-up on foot), HUD with score/best/rivals, objective and warning panel, Grid Shift integrity panel, weapon/nitro readout, flight cooldowns, toasts, captions, and a radar like the browser's. Touch controls: LEFT/RIGHT, FORWARD, FIRE, JET, SAIL, AUTO, PAUSE; Grid Shift adds FORM, an on-foot direction pad, and DISC. Keyboard mirrors the browser (A/D, W, E, Q, R, F, Space, Esc). Results follow the browser's wording and flow (next round, fast retry, rematch, next operation, retry), lost Duel/Arena heats show a six-second crash replay, and badges, records, the eight-run history, operation completions, the Grid Archive lore, and unlockable trail looks persist in PlayerPrefs (RECORDS screen; Trail Look and Sound in Settings). Procedural sound effects and the four-chord music bed follow the browser's synth. All three maps render with their palettes and obstacles; rivals' trails carry style bands so they differ by more than colour.

Deliberate differences from the browser: the Play lesson completes after six clear seconds following the second turn (the browser has no success path); an Arena heat that times out with the player alive counts as survived (the browser throws on that draw); saved-run highlight playback from the archive is not ported.

**Verification.** `android-game/scripts/Verify-Solo.ps1` builds the combined desktop player and drives every mode through its real controls from clean local storage (desktop-only storage reset): **96/96 checks** including relative turns, rendered heading, FIRE ammo use, jet, pause, manual drive, crash replay, heat results and round 2, Arena fading walls with three rivals, the Daily seed/map/rival, Grid Shift dismount/pad movement/disc throw and return/remount, a browser-recorded winning Portal Run route with its amber unlock, the System Sweep lane mark, Arena Collapse warning, Journey with Sentinel (1/4), lesson completion, records, trail look selection, Solar Transit navigation, and control fit at phone 1170x540, desktop 1280x720, and tablet 1024x768. Screenshots were reviewed. No physical-device play, performance, or accessibility audit is claimed. The same session's regression runs passed: rules parity (29/29 scenarios exact), Solar Transit 33/33, two-client online 50/50, Phase 0 probe, and showroom 28/28. `GridRun.Editor.PhaseFourBuild.BuildAndroidRelease` built `grid-run-phase4-release.apk` with all modes (36,400,612 bytes; SHA-256 6F8C5FD522605AF209216F390364243E998EDE5A54D5553F04F5BE8EDC231B94); it has not been installed on a phone or deployed.
