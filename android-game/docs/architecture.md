# Phase 0 architecture decision

Date: 2026-10-17. Direction authorized by the user's request to start Phase 0.

## Decision

Use Unity 6000.3.26f1 LTS, C#, and URP in a separate `android-game/` project. The existing static site and Node server continue as the browser baseline. This phase adds no backend, purchase SDK, analytics service, or account system.

The package manifest pins URP 17.3.0 and uGUI 2.0.0, both confirmed in the installed Editor's bundled package manifests. Editor import is the authoritative package-resolution check; the public registry listing does not establish availability of Editor-bundled packages. Record the resolved lockfile and any justified version adjustment after import. Unity licensing must be activated by the user; commercial eligibility is not assumed.

## Boundaries

- `ProbeSimulation` owns fixed-step position, heading, cooldown, and boundary state. It has no Unity references.
- `ArenaProbe` adapts input and renders state; it does not use Rigidbody physics to decide gameplay movement.
- The probe runs at 120 simulation steps per second, with rendering targeting 60 or 30 FPS. Input and gameplay timing must remain independent of render rate.
- uGUI supplies safe-area-aware touch controls. Legacy Unity input is sufficient for the probe; moving to the Input System later requires an explicit input migration and multi-touch/controller checks.
- URP settings and a scene are generated by an explicit Editor command, then become ordinary editable Unity assets. They are not regenerated every launch.
- Scene creation is idempotent and uses persisted material references to avoid stripping required runtime shaders.
- Versioned persistent progress, purchases, and network protocol handling belong to later phases.

**Revision 2026-10-22 (offline modes).** Gameplay rules for every solo mode now come from `Runtime/Sim/` (namespace `GridRun.Sim`), a plain C# port of the browser rule modules with no Unity references. The browser stays the source of truth: `scripts/sim-traces.mjs` records reference traces and `Editor/SimParity.cs` requires the port to reproduce them exactly (`scripts/Verify-SimParity.ps1`). Any rule change must be made in both and re-checked. Presentation lives in `Runtime/Solo/` (SoloGame flow, SoloWorld rendering, SoloHud, SoloProfile storage, SoloAudio) and maps simulation `(x, z)` to Unity `(x, -z)` so relative turns read correctly on screen. The earlier `ArenaMatch` two-rider rules were retired; Solar Transit keeps its separate `TransitRun` scene.

## Rendering baseline

Use an unlit stylized arena with 2x MSAA, HDR disabled, no depth/opaque copy, no real-time shadows, and 0.85 render scale. This establishes a simple mobile baseline; it is not the final commercial art direction or a claim of performance. The first scene has a procedural cycle, luminous grid and boundaries, and a steady following camera.

Phase 1 should replace prototype geometry with authored models and improve lighting/effects within measured budgets. Add quality presets based on physical-phone evidence. Do not use expensive effects solely because the engine supports them.

**Revision 2026-10-22 (Grid look).** At the user's request for a more realistic TRON look, the shared presentation moved from flat unlit colours to: URP Lit glossy materials for the cycle, rider, and structures; HDR (32-bit R11G11B10 buffer) with bloom (quarter-res, clamped), ACES tonemapping, colour adjustment, and vignette; a procedural HDR environment cubemap for reflections; exponential fog; a camera-centred sky dome; and a half-resolution planar floor reflection. All of it lives in `Runtime/GridLook.cs`, the shaders in `Shaders/`, and materials regenerated by `Editor/GridLookAssets.cs` on every Prepare. The art is still procedural code (`Runtime/GridMesh.cs`, `Runtime/CycleVisual.cs`); no external assets were added. A persisted Graphics HIGH/LOW setting (now in the main menu's Settings) disables HDR, post-processing, and the reflection camera. High doubles scene draw work for the reflection pass. MSAA 2x and 0.85 render scale are unchanged. The first Galaxy M35 session (2026-10-23) held a steady 60 fps at High with no throttling; see `device-validation.md`. Light-wall shading clamps its interpolated height so MSAA edge samples on thin faces cannot produce Inf/NaN, which bloom would otherwise spread across the screen.

**Revision 2026-10-23 (device build).** Release players strip Unity's unused physics module, so `GameObject.CreatePrimitive` (which adds a collider) logged an error on the phone. Cubes and the sky dome now come from `GridMesh` through `GridLook.Cube`; nothing in the game uses physics colliders. Avoid `CreatePrimitive` and `AddComponent<…Collider>` in runtime code.

## Android identity and data

`com.gridrun.prototype` is a development identifier only; the product name is now **Grid Run** (v0.5.1). ARM64 IL2CPP and OpenGL ES 3 are the first build configuration. API 29 is a provisional compatibility floor; API 36 is an explicit build target, not a permanent store-policy claim. Landscape supports both left and right rotation and respects display cutouts.

There is no gameplay telemetry or player data transmission. Local records and settings stay in PlayerPrefs; the Online Room sends only room and input traffic to the Node server. Device evidence is local and ignored. Use debug signing only; a production key and final app identity are separate release decisions. Website downloads come from GitHub Releases through the tracked `dist/android-release.json` (`scripts/publish-android-release.mjs`).

## Migration and later multiplayer

Port behavior from the browser by explicit parity checks. Do not claim cross-play from similar-looking movement. At Phase 2, test a Unity client against the existing Node service and compare that with a C# authoritative server sharing the simulation. Choose based on latency, maintainability, and measured resource use before adding providers.

## Assets and ownership

Visuals and audio are procedural project code plus Unity-provided fonts and shaders. No external art, music, or purchased assets are introduced. Future assets need recorded provenance and redistribution rights. Public branding remains a release decision.

## Known limitations

The original Phase 0 probe had no trails, AI, weapons, scoring, save data, online play, or shop; the app now has all of those except a shop (the cosmetic showroom is excluded from Android builds and has no checkout). Remaining gaps: online play is not yet in a released APK (in source since 2026-10-26 it covers Arena, Duel, and Grid Shift for 2-4 seats on all maps, drawn, controlled, and voiced like solo play; the v0.5.1 APK has two-seat Classic Grid Arena only); signing and app identity are not production; device validation is one short Galaxy M35 session; art is procedural code rather than authored models.
